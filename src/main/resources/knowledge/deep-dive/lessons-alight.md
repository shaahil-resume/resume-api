From the Alight work, Shaahil learned that migrating a module is mostly a reading exercise. Because the logic was divided across several applications, he had to read through the code and understand the whole codebase before deciding how to move each piece. He learned to ship changes that span applications in a fixed order, RI then MSS then SITE, across multiple releases, with review in colour-coded environments by the client, the business analysts and the testers before production. And he found that for slow screens, the biggest improvement came from fetching only the data needed, from the correct tables.
